# SecAgent 安全审计报告

| 项目 | 内容 |
|------|------|
| 被审计对象 | SuperBizAgent（Spring Boot 3.2 + Spring AI / Spring AI Alibaba 教学项目） |
| 审计基线版本 | SuperBizAgent-release-2026-05-17 |
| 改造后版本 | SecAgent 1.0（网络安全智能问答与辅助分析系统） |
| 审计方法 | 白盒代码审计（人工 + 数据流分析）、接口测试、依赖检查 |
| 审计范围 | 认证授权、文件上传、会话管理、CORS、异常处理、RAG/Agent 数据安全、配置 |
| 报告性质 | 课程/教学项目的安全加固，不构成对任何真实产品的评估结论 |

---

## 一、总体结论

对原始工程进行白盒审计后，发现 **1 个高危、2 个中危、3 个低危** 安全问题，集中在文件上传、鉴权、数据安全与信息泄露四个方面。其中 **文件上传接口存在路径穿越（CWE-22），可被利用向上传目录之外写入文件**，风险最高。

审计后对全部问题进行了修复，并通过 JUnit 回归测试与本地 PoC 验证。同时结合 RAG/Agent 特性，补充了**入库前敏感信息扫描（DLP）**这一针对大模型应用的数据安全控制。

### 风险统计

| 风险等级 | 数量 | 已修复 |
|----------|------|--------|
| 高危 | 1 | 1 |
| 中危 | 3 | 3 |
| 低危 | 2 | 2 |

## 二、风险评级标准

| 等级 | 判定依据 |
|------|----------|
| 高 | 可未授权导致任意文件写入、代码执行、敏感数据泄露 |
| 中 | 需要一定条件可越权访问、消耗资源、扩大攻击面 |
| 低 | 信息泄露、安全配置不规范，辅助其他攻击 |

## 三、漏洞详情

### 漏洞 1：文件上传路径穿越 / 任意文件写入（高危）

| 项 | 内容 |
|----|------|
| 编号 | SEC-01 |
| 等级 | 高危 |
| CWE | CWE-22（路径穿越）、CWE-434（不限制文件类型上传） |
| 位置 | `FileUploadController`（原 `uploadDir.resolve(originalFilename)`） |
| 状态 | 已修复 |

**描述**：上传接口直接使用 multipart 中的 `originalFilename` 拼接目标路径，未做白名单与边界校验。该字段由客户端控制，构造 `../`、绝对路径、Windows 盘符等文件名可跳出上传目录。

**危害**：攻击者可写入任意目录；若结合服务端解析的扩展名（如 `.jsp`），可导致 WebShell 与远程代码执行；至少可覆盖关键文件、植入恶意内容。

**PoC（本地）**：
```
curl -X POST http://localhost:9900/api/upload \
  -F "file=@x.md;filename=../../../../tmp/poc.txt"
```
修复前：文件被写到上传目录之外；修复后：返回 `400 文件名包含非法字符或路径`。

**修复**：
1. 新增 `PathSecurityUtil`：字符白名单、拒绝分隔符/空字节/盘符/`..`、Windows 保留名、扩展名白名单（默认 txt/md）；
2. 落盘前 `normalize()` 并校验结果路径必须位于上传目录内（`startsWith`）；
3. 限制单文件大小 10MB；上传目录与可执行目录隔离；
4. 一次性读取字节，先扫描后落盘，避免临时文件残留。

**回归**：`PathSecurityUtilTest` 7 组用例全部覆盖。

### 漏洞 2：知识库敏感信息泄露（中高危）

| 项 | 内容 |
|----|------|
| 编号 | SEC-02 |
| 等级 | 中高危 |
| 参考 | OWASP LLM06（敏感信息泄露）、CWE-200 |
| 位置 | 文档入库链路（`VectorIndexService` / 上传接口） |
| 状态 | 已修复 |

**描述**：RAG 会把上传文档切片向量化并持久化。原始工程未对内容做任何检查，AccessKey、私钥、口令、JWT 一旦入库，会被长期保存并可通过问答套取。

**修复**：新增 `SensitiveContentScanner`，入库前正则识别云 AccessKey、`sk-`、PEM 私钥、JWT（高危，直接拦截）与硬编码口令（中危，可配置）。命中高危返回 422 且不写盘、不入库。

**回归**：`SensitiveContentScannerTest` 6 组用例，含正常文档不被误杀。

---

### 漏洞 3：接口缺少鉴权（中危）

| 项 | 内容 |
|----|------|
| 编号 | SEC-03 |
| 等级 | 中危 |
| CWE | CWE-306（关键功能缺少认证） |
| 位置 | 所有 `/api/**` 接口 |
| 状态 | 已修复（可配置） |

**描述**：所有接口匿名可访问，可被任意调用、消耗大模型额度、访问他人会话与系统状态。

**修复**：`ApiTokenInterceptor` 校验 `X-API-Token`，常量时间比较；健康检查白名单；`app.auth.enabled` 控制开关，默认关闭便于本地演示，生产建议开启。

---

### 漏洞 4：跨域资源共享（CORS）全通配（中危）

| 项 | 内容 |
|----|------|
| 编号 | SEC-04 |
| 等级 | 中危 |
| CWE | CWE-942（过度宽松的跨域策略） |
| 位置 | `WebMvcConfig` |
| 状态 | 已修复 |

**描述**：原配置 `allowedOriginPatterns("*")` 且允许凭据，任意网站可携带用户凭据跨域调用。

**修复**：改为可配置来源白名单，默认仅放行 `http://localhost:9900`、`http://127.0.0.1:9900`。

---

### 漏洞 5：会话无过期、无上限、可越权（中危）

| 项 | 内容 |
|----|------|
| 编号 | SEC-05 |
| 等级 | 中危 |
| CWE | CWE-770（资源无限制）、CWE-384（会话管理） |
| 位置 | `ChatController` 的 `ConcurrentHashMap` 会话存储 |
| 状态 | 已修复 |

**描述**：会话无 TTL、无数量上限，可被制造大量会话耗尽内存；会话 ID 客户端可控，缺少归属校验。

**修复**：增加 TTL（默认 120 分钟，惰性清理）与数量上限（默认 1000，LRU 淘汰）；配合接口鉴权，给出生产环境会话与用户绑定的改进方向。

---

### 漏洞 6：异常信息回显（低危）

| 项 | 内容 |
|----|------|
| 编号 | SEC-06 |
| 等级 | 低危 |
| CWE | CWE-209（错误信息包含敏感内容） |
| 位置 | 各 Controller 的 catch 分支 |
| 状态 | 已修复 |

**描述**：把 `e.getMessage()` 甚至堆栈直接返回前端，可能泄露内部路径、依赖版本、SQL 等。

**修复**：`GlobalExceptionHandler` 统一处理，返回正确状态码与通用提示，详细信息仅写服务端日志。

## 四、面向大模型应用的额外安全控制

结合 OWASP LLM Top 10，除 SEC-02 外还做了：
- **工具最小化（缓解 LLM07/LLM08）**：Agent 工具只读、限定安全分析，不提供任意命令执行/文件写入。
- **提示词约束（缓解 LLM01）**：系统提示词限定安全助手人设，只依据工具返回与知识库作答，拒绝非法用途。
- **调用配额与鉴权（缓解 LLM09）**：接口 Token + 上传大小限制，降低额度被滥用风险。
- **资源治理（缓解 LLM04）**：会话 TTL/上限、可控的知识库分片规模。

## 五、加固前后对比

| 维度 | 加固前 | 加固后 |
|------|--------|--------|
| 文件上传 | 任意文件名、任意类型 | 白名单 + 边界校验 + 大小限制 |
| 数据安全 | 文档原样入库 | 入库前 DLP 扫描拦截 |
| 鉴权 | 全部匿名 | 可选 Token 鉴权 |
| CORS | `*` | 来源白名单 |
| 会话 | 无 TTL/上限 | TTL + 上限淘汰 |
| 异常 | 回显堆栈 | 统一脱敏、正确状态码 |
| 外部依赖 | 强依赖 Milvus | 抽象 + 默认内存实现，攻击面与部署门槛同时下降 |

## 六、残余风险与后续建议

1. 当前 Token 为静态共享密钥，生产应替换为 JWT/OAuth2 + 会话与用户绑定，做水平越权校验。
2. 内存向量库面向学习/演示，生产环境建议切换到 Milvus，并开启认证、按租户/密级做检索权限隔离。
3. 建议增加 WAF/限流（如登录、研判、上传接口的频率限制），防止 LLM 资源滥用与刷接口。
4. 对模型输出做二次安全过滤（URL、代码块、间接提示注入），不直接执行模型输出。
5. 建议接入 SAST（如 SpotBugs/Find Sec Bugs）、依赖 SCA（OWASP Dependency-Check）与 CI 安全门禁。
6. 本审计为教学项目自测，未覆盖完整渗透测试与压测；上线前应进行专业渗透测试。
