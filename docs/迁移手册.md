# SecAgent 迁移手册

> **用途**：服务器到期、想换服务商、或者机器坏了需要重建时，照这个走。
>
> **一句话结论**：**地址不用改，DNS 不用碰。** 这是当初买域名 + 用隧道而不是直接开端口
> 换来的东西，现在兑现。

---

# 一、为什么换机很容易

| 换机时通常最痛的事 | 我们的情况 |
|---|---|
| 域名解析要改、要等生效 | ❌ **不用改** —— DNS 指向 Cloudflare，从不指向服务器 |
| 证书要重签 | ❌ 不用 —— Cloudflare 边缘的证书 |
| 客户端要更新地址 | ❌ 不用 —— `demo.xiaokeqing.cn` 一个字都不动 |
| 数据丢失 | ✅ 每日备份 + **恢复演练验证过** |
| 配置凭记忆重配 | ✅ 已收进备份的 `host/` 目录 |
| 代码版本不一致 | ✅ 两个仓库都在 GitHub |

**核心机制**：

```
demo.xiaokeqing.cn  ──►  Cloudflare 的边缘节点（永远不变）
                              │
                              ▼  隧道（服务器主动出站建连）
                        新服务器 / 旧服务器 —— 换掉这一层，外面完全无感
```

# 二、换机前：先确认备份是新的

```bash
# 在旧机器上
ssh root@<旧机器>
bash /root/backup.sh              # 立刻做一份
bash /root/backup.sh --verify     # 确认业务数据能恢复 + 换机必备项齐全
```

**`--verify` 会逐项点名检查**，缺哪项会明确报出来：

```
[有] host/crontab.txt              定时任务
[有] host/cloudflared-token        隧道凭据
[有] host/cloudflared.service      隧道 systemd 单元
[有] host/system-info.txt          系统快照
[有] docker-compose.yml            编排配置
[有] .env                          凭据与配置
```

然后拉到本地：

```bash
# 在开发机上
scp root@<旧机器>:/opt/secagent-backups/secagent-<时间戳>.tar.gz ./
```

> ⚠️ 备份包含 `.env` 与隧道 token，**属于敏感文件**。放本地、别进 git、别发人。

**换机之前不要关旧机器** —— 留着做回滚。

---

# 三、换机步骤

## 第 0 步：新机器先加固

```bash
# 把仓库脚本传过去（或在新机器上 git clone）
scp scripts/server-setup.sh scripts/harden-ssh.sh root@<新机器>:/root/

ssh root@<新机器>
bash /root/server-setup.sh      # 基础环境 + Swap + Docker
bash /root/harden-ssh.sh        # 关密码登录、fail2ban、防火墙
```

> ⚠️ **`harden-ssh.sh` 会关掉密码登录**。执行前先确认你的公钥已经能登录，
> 否则会把自己锁在外面。

## 第 1 步：恢复业务数据

```bash
scp secagent-<时间戳>.tar.gz root@<新机器>:/root/

ssh root@<新机器>
mkdir -p /opt/secagent
tar -xzf /root/secagent-<时间戳>.tar.gz -C /opt/secagent
chmod 600 /opt/secagent/.env
ls -la /opt/secagent/          # 应看到 data/ .env docker-compose.yml host/
```

**主机配置先别直接覆盖**，看清楚再动 —— 里面的路径、用户名可能和新机器不一样：

```bash
ls -la /opt/secagent/host/
cat /opt/secagent/host/system-info.txt   # 对照旧机器的发行版 / systemd 版本 / 端口
```

## 第 2 步：装镜像并起服务

两条路，看你怎么迁：

```bash
# 路 A（推荐）：从 GitHub 拉源码，在本地构建好镜像传过去
#   在开发机上：
docker build -t secagent:local .
docker save -o secagent-image.tar secagent:local
scp secagent-image.tar root@<新机器>:/root/
scp scripts/server-deploy.sh root@<新机器>:/root/
#   在新机器上：
ssh root@<新机器> "bash /root/server-deploy.sh"
```

```bash
# 路 B：如果新机器配置够（≥4G），直接在上面构建
git clone https://github.com/xiaokeqing/SecAgent.git /opt/secagent-src
cd /opt/secagent-src && docker build -t secagent:local .
```

起完验证：

```bash
curl -s http://127.0.0.1:9900/api/health
# 期望：{"status":"ok","documentVectors":318,...}
```

**`documentVectors` 必须是 318** —— 数字对不上说明向量库没恢复对。

## 第 3 步：重建隧道（**关键，但地址不用改**）

```bash
scp /opt/secagent/host/cloudflared-token root@<新机器>:/root/tunnel-token.txt
scp scripts/setup-named-tunnel.sh root@<新机器>:/root/

ssh root@<新机器>
chmod 600 /root/tunnel-token.txt
bash /root/setup-named-tunnel.sh
```

**注意：这是同一个隧道 token，所以隧道 ID 不变、DNS 记录也不变。**
脚本跑完 `demo.xiaokeqing.cn` 就应该通了 —— **你不需要碰 Cloudflare 后台任何东西**。

验证：

```bash
curl -o /dev/null -s -w '%{http_code} %{time_starttransfer}s\n' https://demo.xiaokeqing.cn/api/health
```

### 如果 token 丢了怎么办

可以从 Cloudflare API 重新取（token 与隧道 ID 我存在本地 `_deploy/` 目录里）：

```bash
curl -s -X GET \
  "https://api.cloudflare.com/client/v4/accounts/<account_id>/cfd_tunnel/<tunnel_id>/token" \
  -H "Authorization: Bearer <cloudflare_api_token>" | python3 -c 'import json,sys;print(json.load(sys.stdin)["result"])'
```

**实在都没有，就重建隧道**（会得到新的隧道 ID，需要更新 DNS 记录）：
```bash
# 见 scripts/setup-named-tunnel.sh 顶部的说明；
# 重建后要在 Cloudflare 上把 demo 的 CNAME 指向新的 <新隧道ID>.cfargotunnel.com
```

## 第 4 步：恢复定时任务

```bash
crontab /opt/secagent/host/crontab.txt
crontab -l        # 确认
```

> ⚠️ 这一步最容易漏。漏了的后果是：**备份静默停止，而且不会有任何报错。**
> 所以 `backup.sh --verify` 把 `host/crontab.txt` 列为必备项。

## 第 5 步：恢复安全配置（**按发行版调整，别直接覆盖**）

```bash
ls /opt/secagent/host/security/
```

**不同发行版配置路径不一样，直接覆盖会出问题**：

| 配置 | RHEL 系（Alibaba Cloud Linux / TencentOS） | Debian 系（Ubuntu / Debian） |
|---|---|---|
| 防火墙 | firewalld `/etc/firewalld/zones/public.xml` | ufw `ufw status` |
| SSH drop-in | `/etc/ssh/sshd_config.d/*.conf` ⚠️ **该发行版 `sshd_config` 可能没有 `Include`，drop-in 会静默失效** | `/etc/ssh/sshd_config.d/*.conf` ✅ 有 Include |
| fail2ban | `/etc/fail2ban/jail.d/*.conf` | 同 |

**验证 SSH 配置真的生效了，必须看合并后的结果，不能只看语法**：

```bash
sshd -t        # 只检查语法 —— 语法对不代表配置被读取
sshd -T | grep -E 'passwordauthentication|permitrootlogin|maxauthtries'   # ← 看这个
```

> 这是我在 Alibaba Cloud Linux 3 上真实踩过的坑：
> `sshd_config` 里没有 `Include /etc/ssh/sshd_config.d/*.conf`，
> 所以 drop-in 写了等于没写，而 `sshd -t` 会通过、脚本会报告成功。

# 四、换机后的验证清单

```bash
# 1. 服务健康 + 向量库完整
curl -s http://127.0.0.1:9900/api/health

# 2. 对外域名通（从任意机器）
curl -o /dev/null -s -w '%{http_code} %{time_starttransfer}s\n' https://demo.xiaokeqing.cn/api/health

# 3. 隧道已注册
systemctl is-active cloudflared
journalctl -u cloudflared --since '5 min ago' | grep 'Registered tunnel connection'

# 4. 登录能进（用分析员账号）
curl -s -X POST https://demo.xiaokeqing.cn/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"analyst","password":"<口令>"}' | head -c 120

# 5. 端口没多开
ss -tlnp                    # 应只有 22 和管理用口

# 6. Swap 在
free -m

# 7. 备份任务已恢复
crontab -l

# 8. 红队回归没退化
bash scripts/eval-regression.sh target/sec-agent-1.0-SNAPSHOT.jar
```

**第 8 条最有价值**：它一次性验证了「数据恢复对了、配置没丢、防护还在工作」。

# 五、回滚

**换机期间旧机器不要关。**

如果新机器起不来，只需在 Cloudflare 后台把隧道的路由改回旧机器
（或者重新在旧机器上跑一次 `setup-named-tunnel.sh`）—— 旧机器隧道一上线，
`demo.xiaokeqing.cn` 立刻恢复。

**因为隧道 ID 和 DNS 都没变，回滚只是「把隧道重新连回旧机器」，不是「改域名解析」。**

# 六、换到「别家」也一样

只要新服务商能满足三条：

1. **能装 Docker**
2. **能装 cloudflared**（需要出站访问 Cloudflare 的 7844 端口）
3. **能开 22 端口**做管理（或者你接受用别的方式进）

**不要求**：
- ❌ 不需要备案（域名的 NS 在 Cloudflare，从不解析到这台机器）
- ❌ 不需要公网固定 IP（隧道是出站连接，IP 变了也自动重连）
- ❌ 不需要开放 80 / 443

**系统建议**：能用 **Ubuntu 22.04 LTS** 就用 Ubuntu。
原因见上面那张发行版差异表 —— RHEL 系有 `sshd_config` 无 `Include` 的坑，
systemd 也可能偏老（Alibaba Cloud Linux 3 是 239，不支持 `StandardOutput=append:`）。

# 七、这套流程本身也是简历素材

「**把服务器当消耗品、把域名和隧道当资产**」—— 这个取舍能讲清楚三件事：

1. 你理解**故障域隔离**（服务和数据不在同一层）
2. 你知道**什么该持久、什么不该持久**（域名持久，服务器不持久）
3. 你会为「一年后才会发生的事」**提前留后路**（备份带主机配置、迁移手册、回滚方案）

面试官问「你这台机器到期怎么办」，答案是现成的。
