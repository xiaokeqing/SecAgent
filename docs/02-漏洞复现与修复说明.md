# 漏洞复现与修复说明（PoC 操作手册）

> 目标：在**自己本地**的 SecAgent 上复现原始工程的安全问题，验证修复效果。所有操作仅针对 `http://localhost:9900`，请勿用于任何未授权目标。
> 一键脚本：`docs/poc/windows-poc.bat`（Windows）或 `docs/poc/poc.sh`（Git Bash）。

---

## 漏洞一：任意文件上传 / 路径穿越（CWE-22 / CWE-434，高危）

### 1.1 原始问题代码（修复前）

```java
// 原 FileUploadController
String filename = file.getOriginalFilename();
Path filePath = uploadPath.resolve(filename);      // 直接拼接客户端文件名
Files.createDirectories(filePath.getParent());
file.transferTo(filePath);                          // 未做任何校验即落盘
```

`getOriginalFilename()` 来自 multipart 请求头，**完全由客户端控制**。攻击者把文件名构造成 `../../../../tmp/poc.txt`，`resolve` 后路径会跳出上传目录，实现**任意目录写入**；再结合 `.jsp`/`.html` 扩展名可升级为 WebShell / 存储型 XSS。

### 1.2 修复方案（修复后）

1. 新增 `PathSecurityUtil`：
   - 白名单字符 `^[\u4e00-\u9fa5A-Za-z0-9._() -]+$`，拒绝 `/`、`\`、`:`、空字节、`%` 编码；
   - 拒绝 `..` 路径穿越与 Windows 保留名（NUL/CON/COM1…）；
   - 扩展名取**最后一个点**白名单（默认仅 `txt/md`），防 `x.jsp;.jpg`、`x.php.jpg` 绕过；
   - `resolveWithin` 落盘后再做 `normalize() + startsWith(base)` 二次校验（纵深防御）。
2. 上传改为**一次性读取字节**，先做安全扫描、再落盘到受控目录，成功后删除临时文件。
3. 配置项收敛：`file.allowed-extensions`、`spring.servlet.multipart.max-file-size=10MB`。

### 1.3 复现与验证

```bat
# Windows（在项目根目录、应用已启动）
# 正常上传：期望 200
curl.exe -X POST http://localhost:9900/api/upload -F "file=@security-docs/01-OWASP-Top10-安全概览.md"

# 路径穿越：期望 400 文件名包含非法字符或路径
curl.exe -X POST http://localhost:9900/api/upload -F "file=@security-docs/01-OWASP-Top10-安全概览.md;filename=../../../../../../Windows/Temp/poc.txt"

# 编码绕过：期望 400
curl.exe -X POST http://localhost:9900/api/upload -F "file=@security-docs/01-OWASP-Top10-安全概览.md;filename=..%2f..%2fpoc.txt"

# 非法扩展名：期望 400
curl.exe -X POST http://localhost:9900/api/upload -F "file=@security-docs/01-OWASP-Top10-安全概览.md;filename=shell.jsp"
```

### 1.4 修复原理小结

- 不信任客户端文件名，用"白名单 + 规范化 + 目录边界校验"三重防护；
- 上传目录限定扩展名、大小，并与可执行目录隔离。

## 漏洞二：知识库无敏感信息管控（LLM06 / CWE-200，中高危）

### 2.1 问题

RAG 会把文档切片后向量化入库。若有人上传含 **AccessKey、私钥、口令、JWT** 的文档，这些秘密会被长期保存并可被任何提问套取——这是大模型应用特有的数据泄露面（OWASP LLM06 敏感信息泄露）。

### 2.2 修复：入库前 DLP 扫描

新增 `SensitiveContentScanner`，在上传与入库前对字节内容做正则检测：

| 规则 | 命中样例 | 级别 |
|------|----------|------|
| 阿里云 AccessKey | `LTAI5t...` | 高危 |
| AWS AccessKey | `AKIA...` | 高危 |
| OpenAI 风格 Key | `sk-...` | 高危 |
| PEM 私钥 | `-----BEGIN PRIVATE KEY-----` | 高危 |
| JWT | `eyJ...` | 高危 |
| 硬编码口令 | `password=...` / `secret=...` | 中危 |

- 高危：**直接拦截**（HTTP 422），禁止落盘与入库；
- 中危：由 `file.sensitive-strict` 控制是否拦截，默认只告警。

### 2.3 验证

```bat
echo LTAI5t7abcdefghijklmnop> secret-demo.txt
curl.exe -X POST http://localhost:9900/api/upload -F "file=@secret-demo.txt;filename=secret-demo.md"
:: 期望：422，提示"检测到敏感信息，禁止入库"
```

### 2.4 单元测试

`src/test/java/org/example/security/SensitiveContentScannerTest.java` 覆盖 6 类场景，含正常安全文档不被误杀。

## 漏洞三：接口完全无鉴权（CWE-306 / CWE-306，中危）

### 3.1 问题
原工程所有 `/api/**` 接口匿名可用，任何人可上传文件、调用大模型（消耗额度）、查看会话与 Milvus 状态。

### 3.2 修复
新增 `ApiTokenInterceptor`：
- 读请求头 `X-API-Token`，与配置 token 做**常量时间比较**（防时序侧信道）；
- 默认 `app.auth.enabled=true`（升级版默认开启鉴权），接口同时支持登录会话 Token 与系统级 API Token（默认 `secagent-demo-token`）；
- 白名单放行 `/api/health`。

### 3.3 验证
```bat
# 鉴权默认开启（app.auth.enabled=true），无需改配置
# 不带 Token（期望 401）
curl.exe -i http://localhost:9900/api/chat/session/list
# 带 Token（期望正常）
curl.exe -H "X-API-Token: secagent-demo-token" http://localhost:9900/api/health
```

## 漏洞四：CORS 全通配（CWE-942，中危）

### 4.1 问题
原配置 `allowedOriginPatterns("*")` + `allowCredentials(true)`，任意站点可跨域带凭据调用接口。

### 4.2 修复
CORS 收敛为可配置白名单：
```yaml
app:
  cors:
    allowed-origins: http://localhost:9900,http://127.0.0.1:9900
```
默认仅允许本机来源，按部署需要显式加白。

## 漏洞五：会话管理缺陷（CWE-384 / CWE-770，中危）

### 5.1 问题
原 `ChatController` 用 `ConcurrentHashMap<String, SessionInfo>` 存会话：
- 无数量上限、无过期 → 内存无限增长（拒绝服务）；
- 会话 ID 由客户端传入、未与用户绑定 → 可枚举/越权读取他人会话。

### 5.2 修复
- 会话增加 `lastAccessTime`，访问时惰性清理过期会话（`app.session.ttl-minutes`，默认 120 分钟）；
- 会话数量上限（`app.session.max-sessions`，默认 1000），超限淘汰最久未用；
- 配合接口鉴权，生产环境可进一步做会话-用户绑定。

## 漏洞六：异常信息直接回显（CWE-209，低危）

### 6.1 问题
原代码把 `e.getMessage()` 直接写进响应，异常发生时可能泄露内部路径、SQL、依赖版本、堆栈。

### 6.2 修复
新增 `@RestControllerAdvice` 全局异常处理器 `GlobalExceptionHandler`：
- 业务异常返回 400/413/422 等正确状态码与通用提示；
- 未预期异常统一返回 500「服务器内部错误」，详细堆栈只记服务端日志；
- 拦截器拒绝时返回 401 标准 JSON。
