# SecAgent 项目架构与技术讲解

> 项目名：**基于 Spring AI 的网络安全智能问答与辅助分析系统（SecAgent）**
> 定位：在 Spring AI Alibaba 教学项目基础上**二次开发**，把 RAG 与多 Agent 能力落到网络安全场景，并对原始工程做了系统性安全加固。

### 多智能体编排层（本轮升级，核心）

本轮把对话研判从「单智能体一把梭」升级为**编排层 + 调度员 + 三个专职智能体**：

```text
用户输入（对话页提问）
  → MultiAgentCoordinatorImpl（编排层 agent/multi/）
       PLANNER 调度员：规则关键词路由（离线默认）/ 模型路由（配 Key 时）
                     解析失败 / 无真实 Key → 自动回退规则路由
       ├─ ANALYST 研判分析员：工具=知识库 RAG + 时间，只依据知识库内容作答
       ├─ FORENSICS 取证分析员：工具=告警指标 + 安全日志 + 时间，只输出工具返回事实
       └─ RESPONDER 处置执行员：工具=SecurityActionTools + 时间
                                  └─ 内部强制走 ResponseActionService
                                     （ResponseGuard 白名单护栏 → 高危人工审批 → 审计留痕）
       → 汇总输出：结论 + 证据 + 处置结果
       → /api/chat 返回 steps 数组，前端渲染「智能体协同过程」时间线
```

要点：
- **处置安全靠代码强制，不靠提示词**：RESPONDER 即使被诱导想封内网 IP，SecurityActionTools 内部也会先走 ResponseGuard（环回/私网/非法 IP/超长时长拦截），高危再转人工审批，最后落审计。
- **离线可演示**：无真实 Key 时调度自动回退规则路由，取证/处置照常工作，四类任务路由可完整演示。

同层还补齐三块运营闭环能力：**告警聚合去重**（`aggregation/AlertAggregationService`，按 源 IP + 时间窗 + 类型 分桶）、**封禁到期自动解封**（`UnblockScheduler` 定时扫描 `data/blocked-ips.json`）、**红队评测误报率**（19 例含 8 条正常流量，统计误报率，与绕过率两维度独立）。

## 二、两条核心链路

### 链路 1：知识库问答（RAG，Retrieval-Augmented Generation）

```text
用户提问
  → ChatController.chat()
  → RagService
       ① VectorSearchService.search(query)
            - 调 Embedding 模型把「问题」转向量
            - 在向量库按余弦相似度取 Top-K 文档片段
       ② 把检索到的片段拼进 Prompt（上下文）
       ③ 调 ChatModel 让大模型「只依据这些资料」回答
  → 返回带引用的答案
```

**为什么需要 RAG**：大模型本身不懂你的私有知识库、可能"一本正经胡说"。RAG 先检索再生成，让回答有出处、可溯源、可控。

**入库侧（离线/启动时）**：
```text
security-docs/*.md
  → 读取 → 按 800 字切片（100 字重叠）
  → 敏感信息扫描（DLP，拦截密钥）
  → Embedding 向量化
  → 经 VectorStoreGateway 存入（默认内存 + JSON 持久化）
```
预置向量已随包提供（`data/vector-store.json`，318 条），启动默认不重新向量化；如需重建，把 `vector.kb.auto-index` 改为 `true` 或由 `KnowledgeBaseInitializer` 触发，向量持久化后重启不重复花钱。

### 链路 2：安全事件研判（多 Agent + Tool Calling）

```text
点击「安全研判」
  → ChatController.aiOps()
  → AiOpsService（基于 Spring AI Alibaba 的 ReactAgent / SupervisorAgent）
       Planner Agent（规划，输出 planner_plan）
         → Executor Agent（执行，ReAct：思考→调用工具→观察→再思考）
              · QueryMetricsTools.getCurrentActiveAlerts()  拉活跃告警
              · QueryLogsTools.queryLogs(主题,时间)         查日志印证
              · InternalDocsTools                          查处置知识库
         → Executor 反馈（输出 executor_feedback）
       Supervisor Agent（汇总，形成《安全事件研判报告》）
  → 结果通过 SSE 流式返回前端
```

**ReAct 是什么**：Reasoning + Acting，模型不是一次给答案，而是"思考要查什么 → 调用工具拿真实数据 → 观察结果 → 再决定下一步"，最后汇总。这样结论建立在真实告警/日志上，而不是模型想象。

| 技术点 | 在项目中的体现 |
|--------|----------------|
| Spring AI / Spring AI Alibaba | ChatModel、EmbeddingModel、Tool Calling、Agent 框架 |

## 五、为什么做向量存储抽象（这是重要的设计能力点）

原工程把代码**硬耦合到 Milvus**（直接注入 `MilvusServiceClient`），导致：
- 没启动 Milvus 应用就无法启动；
- 学习者普通笔记本跑不动；
- 想换向量库要改一堆业务代码。

改造后引入 `VectorStoreGateway` 接口（`upsert/deleteBySource/search/count/backend`），业务层只依赖接口：
- 用 `vector.store=memory` 时装配内存实现（ConcurrentHashMap + JSON 落盘 + 余弦相似度），零外部依赖；
- 用 `vector.store=milvus` 时装配 Milvus 实现（沿用原生产级代码）。

这体现了**面向接口编程、依赖倒置、可移植性**，是面试中可以展开讲的设计点。
