# 清理「公开面自测封禁留痕」18 条（2026-10-18）

> 一句话：`GET /api/public/audit.js` 的 `blocks[]` 里有 18 条**开发期自测**封禁（不是真实攻击处置），
> 因为公开面的评测过滤只认 `evalRunId` / `actor` 前缀这两个标记，而自测是走正常调用写进去的。
> 清理用 `scripts/purge-selftest-audit.sh`（默认 dry-run），只删这 18 条 id+ip 同时命中的记录。

## 1. 现象（srv1 实读，非估算）

`/opt/secagent/data/blocked-ips.json`：共 **18** 条，全部 `unblocked=true`、`blockActive=0`。

| 维度 | 实测分布 |
|---|---|
| IP（7 个） | `1.2.3.4`×8、`45.83.91.55`×4、`45.83.91.77`×2、`45.83.91.66`/`45.83.91.88`/`45.83.91.12`/`198.18.0.9` 各 ×1 |
| 时长 | 60 min×10、30 min×4、10 min×3、5 min×1（**不是全部 60**） |
| source/actor | 智能体 `responder-agent`×10、手动 `admin`×8 |
| unblockMode | REAL×12、MOCK×6 |

线上（`curl https://demo.xiaokeqing.cn/api/public/audit.js`）：
`summary = {"blockTotal":18,"blockActive":0,"blockedByGuard":98,"executedActions":36}`、`blocks` 长度 18、`cacheSeconds:45`。

处置流水 `response-audit.json` 里另有 **36 条**（134 条中的）`block-ip`/`unblock-ip` 记录 `target` 就是这 7 个 IP
（actor：`admin`×8、`scheduler`×18、`responder-agent`×10）——所以只清封禁表，`actions[]` 里仍会看到这些 target。

## 2. 为什么公开面会带出这些记录

三处代码 + 一处配置，缺一不可：

1. **公开面读的是"全部留痕"，不是"当前生效"**
   `src/main/java/org/example/publicapi/PublicAuditReader.java`：`blocks()` 全量遍历 `blocked-ips.json`，只按 `createdAt` 倒序，**不按 `unblocked` 过滤** ⇒ 解封后的记录照样出现。
2. **唯一的过滤只针对"评测记录"**
   `PublicAuditReader.java:347` 的 `isEvalRecord(JsonNode)` 只认两个标记：`evalRunId` 非空，或 `actor` 以 `EvalIdentity.ACTOR_PREFIX`（`eval-`）开头。
   自测记录当时是人工 / 智能体正常调用写的（`actor=admin`、`responder-agent`），两个标记都没有 ⇒ 原样出海。
3. **写侧从不删记录**
   `src/main/java/org/example/response/BlockRecordStore.java`：`markUnblocked()` 只置 `unblocked/unblockedAt/unblockMode`，`persist()` 取内存快照整体覆盖落盘 ⇒ 到期解封 ≠ 删除留痕。
4. **生产不掩码**
   `src/main/resources/application.yml:326`：`mask-ips: ${APP_PUBLIC_MASK_IPS:false}`，容器里没设这个变量 ⇒ `PublicIpPolicy.masking()` 的显示打码不生效，`1.2.3.4` 原样显示。（`PrivateNetPolicy` 拦的是"封禁动作"，不是"显示"。）

## 3. 数据在哪、什么格式

- 宿主：`/opt/secagent/data/blocked-ips.json`（`mode=600`，owner uid 999 ⇒ 改它要 root/sudo）；
  容器内同一份是 `/app/data/blocked-ips.json`（compose 挂载 `./data:/app/data`，`app.public-api.data-dir=/app/data`）。
- 格式：JSON **数组**，每条形如
  `{"id":"BLK-d9ffbf76","ip":"1.2.3.4","durationMinutes":60,"source":"智能体","actor":"responder-agent","auditId":"AUD-…","createdAt":"2026-10-11 21:41:41","expiresAt":"…","unblocked":true,"unblockedAt":"…","unblockMode":"MOCK"}`；
  读取端同时兼容 `{"records":[…]}` 包装（`PublicAuditReader.readArray`）。
- `response-audit.json` 同目录，记录 `{id,time,actor,action,target,reason,riskLevel,mode,success}`，公开面只输出白名单字段。

## 4. 怎么清

```bash
# srv1，root。脚本在仓库 sec-agent/scripts/ 下；
# ⚠ 本次只改了文件、未 commit/push ⇒ srv1 的 /opt/secagent 上还没有它，
#    先按发布流程把仓库更新到 srv1（git pull / 或 scp 单文件到 /root 下跑也行，
#    它只用 bash + python3，不依赖仓库其它文件），再执行：
cd /opt/secagent                                    # 或用 --data-dir 指数据目录，与 cwd 无关
sudo ./scripts/purge-selftest-audit.sh               # ① 默认 dry-run：只报告，不写
sudo ./scripts/purge-selftest-audit.sh --apply       # ② 真删（先备份 blocked-ips.json.bak-selftest-<UTC>）
sudo ./scripts/purge-selftest-audit.sh --apply --with-audit   # ③ 连处置流水里的 36 条一起清
```

预期输出（dry-run，实测过的口径）：`现有记录 18 条 → 命中 18 条，保留 0 条`，`[dry-run] 将写回 18 → 0 条`。

- **只处理这 18 条**：`blocked-ips.json` 里必须 `id ∈` 18 个 `BLK-…` 且 `ip ∈` 7 个明确 IP，**双键同时命中才删**；只命中单个键的一律不动、只报告。
- **不做通配删除**：不按网段（不删 `45.83.91.0/24`、不删 `198.18.0.0/15`）、不按前缀、不按时间窗、不按 `actor`/`source` 批量删。
- 其它开关：`--no-backup`、`--expect N`（默认 18；命中数≠N 时拒绝动手，需 `--force`）、`--data-dir DIR`（本机演练）。
- 幂等：再跑一次命中 0 条 → 打印「没有可清理的记录」，**不写文件**，`exit 0`。
- 退出码：`0` 正常（含已清过）｜`2` 命中数与 `--expect` 不符且未 `--force`｜`1` 环境/文件错误。
- **要不要加 `--with-audit`**：只清封禁表 ⇒ `blockTotal: 18→0`、`blocks` 空，但 `actions[]` 里这 7 个 IP 的 18+18 条 block/unblock 仍在（`executedActions` 仍为 36）。要"公开面一条都不剩"就加它。

## 5. 清了之后怎么核

```bash
# ① 文件层：条数与残留 IP
sudo python3 -c 'import json;d=json.load(open("/opt/secagent/data/blocked-ips.json"));print(len(d),[r["ip"] for r in d])'
#    期望：0 []

# ② 公开面（缓存 45s，等 ≥60s 再取；CF 侧也可能缓存几十秒）
curl -s https://demo.xiaokeqing.cn/api/public/audit.js | python3 -c 'import json,sys;d=json.load(sys.stdin);print(d["summary"], len(d["blocks"]))'
#    只清封禁表：{'blockTotal': 0, 'blockActive': 0, 'blockedByGuard': 98, 'executedActions': 36} 0
#    加了 --with-audit：executedActions 应同时下降 36

# ③ 备份在不在（回滚用）
ls -l /opt/secagent/data/*.bak-selftest-*
```

**注意（最容易踩）**：`BlockRecordStore` 启动时把整份文件读进内存，之后任何一次封禁/解封都会拿内存快照**整体覆盖**回原样。
所以 `--apply` 后要让清理真正站稳，需要**一次容器/服务重启**（脚本不重启、不重部署）。若暂时不重启，
下一次真实封禁发生时就要重跑一遍脚本 —— 这正是它设计成幂等的原因。

## 6. 后续（根治，不在本次范围）

- 自测/演练封禁应在写入时打标记：`register(..., actor)` 传 `EvalIdentity.ACTOR_PREFIX` 开头的 actor（如 `eval-selftest`），
  `PublicAuditReader.isEvalRecord` 立刻就会把它挡在公开面之外。`BlockRecord` 没有 `evalRunId` 字段，给它补标记会被
  `persist()` 写盘/再读时丢掉，所以别用"外挂字段"的办法。
- 或者：让公开面区分「当前生效」与「历史留痕」，把已解封的折叠/分页，而不是整表倒序全量输出。
