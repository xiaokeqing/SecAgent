# 弱口令、暴力破解与认证安全

## 一、问题本质
弱口令与认证机制缺陷是最常见的入侵入口，长期位居各类安全事件首位。攻击者通过字典猜测、撞库、喷洒等方式获得合法账号，进而正常登录，绕过大多数边界防护。

## 二、常见攻击方式
- **弱口令**：`admin/123456`、`root/root`、公司名+年份、默认口令等。
- **暴力破解（Brute Force）**：对单一账号尝试大量密码。
- **密码喷洒（Password Spraying）**：用少量常见密码批量尝试大量账号，规避账号锁定。
- **撞库（Credential Stuffing）**：用其他网站泄露的账号密码在本系统尝试。
- **默认/硬编码口令**：数据库、中间件、网络设备、摄像头的出厂口令。
- 针对 SSH、RDP、FTP、MySQL、Redis、Web 后台、VPN 的自动化爆破。

## 三、检测特征（日志研判）
- Linux：`auth.log/secure` 中大量 `Failed password` 后出现 `Accepted password`（爆破成功）；
- Windows：事件 4625（登录失败）集中爆发后出现 4624（登录成功）；
- Web：登录接口同一 IP/账号短时大量 POST、验证码绕过、状态码 200/302 变化；
- 源 IP 集中、时间连续、User-Agent 为脚本特征；
- 时间维度：非工作时间、短时间内大量失败。

## 四、防御
1. **强口令策略**：长度（≥12 位）、复杂度、禁止常见弱口令、禁止与用户名/公司名相关。
2. **登录失败锁定与限流**：连续失败锁定账号或 IP、指数退避、滑块/图形/行为验证码。
3. **多因素认证（MFA/2FA）**：SSH、VPN、后台、远程桌面开启二次认证。
4. **统一认证与审计**：集中账号管理（PAM/LDAP/堡垒机）、特权账号管控。
5. **禁用默认口令、改默认端口、管理面不暴露公网**：SSH/RDP/数据库走 VPN/堡垒机。
6. **监测与蜜罐**：登录监控、异地/异常时间告警、部署蜜罐账号诱捕。
7. **密码存储**：服务端用 bcrypt/Argon2 等加盐哈希，禁止明文/MD5 存储。

## 五、密码喷洒 vs 暴力破解的研判区别
- 暴力破解：一账号、多密码、失败量极高，容易触发锁定；
- 密码喷洒：多账号、每个只试 1～2 次，单点失败量低、更隐蔽，需按"全网失败次数"统计。

## 六、与项目 mock 场景
内置告警 `SSHBruteForce`：源 IP 对 `root@web-01` 短时间大量 SSH 登录失败后成功。研判时在 auth.log 中核对 Failed/Accepted 序列，确认是否已登录成功，再检查登录后命令、文件落地与外连（Webshell、C2），并给出封禁 IP、锁定、改密、MFA 等处置建议。
