# 命令注入漏洞（CWE-78 / CWE-77）

## 一、原理
应用把用户输入拼接到操作系统命令中执行，且未做过滤，攻击者可通过命令分隔符插入额外命令，从而在服务器/设备上执行任意命令。

常见危险函数：Java 的 `Runtime.exec`、`ProcessBuilder`；PHP 的 `system/exec/shell_exec/popen`；C 的 `system/popen`；Python 的 `os.system/subprocess(..., shell=True)`。

## 二、命令分隔符
`;`（顺序执行）、`&&`、`||`、`|`（管道）、反引号 `` ` ``、`$()`（命令替换）、`&`（后台）、换行符 `\n`。

示例：`ping` 功能后端执行 `ping -c 4 [input]`，输入 `8.8.8.8; id`，实际执行 `ping -c 4 8.8.8.8; id`，额外执行了 `id`。

## 三、危害
- 远程命令执行（RCE），获取服务权限；
- 反弹 Shell、植入后门、添加管理员；
- 横向移动、数据窃取、作为跳板攻击内网；
- 在 IoT/路由器上常直接拿到 root，是设备类漏洞的高发点。

## 四、常见场景
- ping、traceroute、网络诊断功能；
- 备份、压缩、转换、导出等调用系统工具的功能；
- 路由器/摄像头/IoT 设备的 CGI 程序拼 shell；
- 文件名、主机名、时间参数被拼入命令。

## 五、防御
1. **优先不调用 shell**：用参数化 API/库替代命令行，例如用 `ProcessBuilder` 传数组参数，或用成熟库实现 ping/网络功能，避免字符串拼接。
2. **严格白名单**：对必须输入的参数做格式校验，例如 IP 用正则 `^[0-9a-fA-F:.]+$`、主机名只允许字母数字点连字符，绝不依赖黑名单。
3. **最小权限**：服务以低权限用户运行，禁用不必要的系统命令；IoT 设备移除 Telnet、限制 CGI。
4. **沙箱与隔离**：容器、chroot、系统能力裁剪；网络出站限制，降低反弹 Shell 成功率。
5. **监控**：记录命令执行类日志，对异常子进程、外连行为告警。

## 六、命令注入 vs 其他漏洞
- 命令注入：执行**操作系统命令**；
- 代码注入：执行应用语言代码（如表达式、反序列化）；
- SQL 注入：执行**数据库语句**；
- SSTI 模板注入：执行模板引擎表达式。

## 七、与项目关联
命令注入是 IoT 固件漏洞挖掘的高发点：固件 CGI 把 Web 参数拼入 shell 时，使用 IDA 定位 `system/doSystemCmd` 等函数，回溯参数是否可控，是审计的核心思路之一。
