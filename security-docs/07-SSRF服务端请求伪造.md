# SSRF 服务端请求伪造（CWE-918）

## 一、原理
SSRF（Server-Side Request Forgery）是指应用根据用户提供的 URL 或地址发起网络请求，且没有对目标做限制，攻击者借此让**服务器去请求它指定的地址**。

## 二、典型场景
- 远程图片/头像下载、网页抓取、在线预览、翻译、Webhook；
- 接收一个 URL 参数由服务端发起请求（如 `url=http://...`、`image_url=...`）；
- 云环境中调用元数据接口；
- 大模型/Agent 应用中联网搜索、URL 读取、工具请求外部地址（AI 应用 SSRF 是新攻击面）。

## 三、危害
- **探测内网**：访问 `http://192.168.x.x/`、`http://127.0.0.1/` 等内网服务；
- **读取云元数据**：如 `http://100.100.100.200/latest/meta-data/`（阿里云）、`169.254.169.254`（AWS），获取临时凭据（RAM Role），常导致云主机被接管；
- 访问内部管理后台、Redis、数据库、未授权接口；
- 利用 `file://`、`gopher://`、`dict://` 等协议读取本地文件、攻击内网服务。

## 四、绕过手法
- IP 进制转换（十进制、八进制、十六进制）、IPv6 表示 `[::1]`、`0.0.0.0`；
- DNS 重绑定、短链接跳转、302 跳转；
- 域名解析到内网地址、`@` 符号、特殊符号；
- 用 `xip.io` 之类域名。

## 五、防御
1. **白名单**：只允许请求明确的外部域名/业务地址，不允许任意 URL。
2. **禁止内网地址**：解析目标域名的所有 IP（含跳转后的 IP），拒绝私网段（`10/172.16-31/192.168/127/169.254`）、链路本地地址。
3. **禁用危险协议**：只允许 `http/https`，禁止 `file/gopher/dict/ftp`。
4. **禁止重定向**或对重定向目标重复校验；
5. **网络隔离**：服务出口不放在内网，使用代理/沙箱网关，禁止访问元数据地址（云环境加 IMDSv2 / 限制元数据访问）。
6. **最小权限**：服务使用的云账号权限最小化，避免元数据凭据被滥用。

## 六、与项目关联
多 Agent 若开放"联网查询/抓取 URL"类工具，工具入参（目标 URL）必须做白名单与内网地址校验，否则模型可能被诱导请求内网地址（过度代理 + SSRF）。本项目工具均为只读安全分析，未开放任意 URL 请求，从源头规避该风险。
