# IoT 固件漏洞挖掘通用流程（教学与授权测试）

> 仅适用于拥有授权的安全测试、CNVD/CNNVD 等合规漏洞报送与教学研究。所有操作应在隔离实验环境中进行，严禁用于未授权目标。

## 一、整体流程

固件漏洞挖掘的标准链路：**获取固件 → 解包提取 → 静态分析 → 动态仿真 → 漏洞验证 → 修复建议 → 合规报送**。

## 二、获取与解包

1. **获取固件**：从厂商官网下载升级包，或通过编程器从 Flash 芯片提取。
2. **识别格式**：用 `binwalk` 识别文件系统与压缩格式（SquashFS、JFFS2、UBI、CramFS 等）。
3. **解包**：`binwalk -Me firmware.bin`；遇到厂商私有/加密打包，可结合 `firmware-mod-kit`、UE 或自写解包脚本。
4. **提取文件系统**：得到根文件系统，重点关注 Web 目录（如 /www、/web）、配置文件、/usr/bin、/usr/sbin、启动脚本。

## 三、静态分析（优先，覆盖面广）

1. **定位 Web 服务**：常见 httpd（goahead、uhttpd、lighttpd、mini_httpd 及厂商自研），分析 CGI（C 语言编译的二进制 CGI，或 Lua/Shell 脚本）。
2. **危险函数检索**：在二进制中搜索 `system`、`popen`、`doSystemCmd`、`sprintf`、`strcpy`、`strcat`、`gets` 等，回溯参数是否可被外部输入控制。
3. **命令注入点**：Web 参数（ping、traceroute、网络设置、诊断功能）被拼入 shell 命令且未过滤 `;`、`|`、`&&`、`` ` ``、`$()` 时形成命令注入（CWE-78）。
4. **逆向工具**：使用 IDA Pro / Ghidra 反编译，结合字符串交叉引用定位处理函数；MIPS/ARM 架构注意大小端、延迟槽、寄存器传参。
5. **其他高发漏洞**：硬编码账号口令、后门、栈溢出（CWE-121）、硬编码密钥、敏感信息泄露、未授权访问、路径穿越（CWE-22）。

## 四、动态仿真与验证

1. **用户态仿真**：QEMU 单独运行目标程序（`qemu-mipsel-static -L . ./program`），快速复现。
2. **整系统仿真**：QEMU 启动内核 + 文件系统（或使用 FAT、EMBA 等工具），处理网络初始化、NVRAM 缺失等问题。
3. **流量验证**：Burp Suite 抓包，在 Repeater 中重放并构造 payload，观察响应/时延确认漏洞。
4. **PoC 编写**：最小化、可复现的请求或脚本，截图/录屏证明危害，避免破坏性操作。

## 五、常见漏洞类型与危害

| 类型 | CWE | 典型位置 | 危害 |
|------|-----|----------|------|
| 命令注入 | CWE-78 | 诊断/网络设置 CGI | 远程命令执行、接管设备 |
| 栈溢出 | CWE-121 | 解析请求的二进制 | 代码执行、拒绝服务 |
| 路径穿越 | CWE-22 | 文件下载/读取接口 | 任意文件读取 |
| 未授权访问 | CWE-306 | 管理接口/API | 越权控制设备 |
| 硬编码凭据 | CWE-798 | 配置/二进制 | 批量弱口令 |
| 敏感信息泄露 | CWE-200 | 备份、日志、配置 | 泄露密钥与配置 |

## 六、修复建议（报告必备）

- 命令执行：避免拼 shell，使用参数化 API；对输入做严格白名单（如 ping 只允许 IP 格式）。
- 输入处理：使用安全函数、长度校验、边界检查；输入输出编码。
- 访问控制：所有管理接口强制鉴权；最小权限运行服务。
- 配置：移除硬编码/后门账号，密钥与口令不落地，及时更新组件。

## 七、合规报送要点（CNVD 等）

1. 仅报送授权/自有设备，不公开 0day 细节、不实施破坏。
2. 材料包含：厂商型号、固件版本、漏洞类型、复现步骤、PoC 与截图、危害说明、修复建议。
3. 遵循负责任披露，给厂商修复时间，不擅自传播利用代码。
