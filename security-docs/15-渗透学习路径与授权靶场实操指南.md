# 渗透学习路径与授权靶场实操指南

> 本文所有"测试"均指在**自己搭建、完全隔离、已获授权**的靶场环境中进行。对真实系统做任何未授权扫描、利用、绕过都属于违法行为，不在本文范围。学习渗透的正确姿势是：原理 → 靶场动手验证 → 看懂日志 → 总结防御。

## 一、合法靶场环境搭建

1. 虚拟机：VMware Workstation / VirtualBox，安装攻击机（Kali）与靶机。
2. 网络模式：**NAT 或仅主机（Host-Only）**，靶机不桥接到真实网络，确保攻击流量只在自己的隔离网段内。
3. 快照：靶机和攻击机配置好后做快照，便于回滚。
4. 授权原则：只对自己拥有的靶机和公开靶场平台操作；公开平台也只在其允许范围内测试。

## 二、推荐靶场（按难度递进）

| 类型 | 靶场 | 适合练什么 |
|------|------|-----------|
| Web 入门 | DVWA（PHP，可切 Low/Medium/High） | 各类 Web 漏洞，从无防护到有过滤逐级理解 |
| Web 入门 | Pikachu | 中文、覆盖常见漏洞，适合新手 |
| 专项 | SQLi-Labs | SQL 注入手工闯关 |
| 专项 | Upload-Labs | 文件上传绕过与白名单 |
| 专项 | XSS-Labs | 反射/存储型 XSS |
| 综合主机 | Metasploitable2 | 多服务漏洞综合练习 |
| 综合主机 | VulnHub（DC 系列、Mr-Robot 等） | 主机渗透完整链路（DC-1 已做过） |
| 在线平台 | TryHackMe、Hack The Box | 体系化房间与靶机 |
| 国内 | 攻防世界、墨者学院、i 春秋、BUUCTF | 中文引导、CTF 与漏洞题 |

## 三、学习顺序（对应短训课程）
1. 系统与服务基础：Windows/Linux 命令、网络、常见服务搭建；
2. 网络基础：路由交换、NAT、防火墙区域；
3. Web 与代码：HTML/JS/PHP/Python，看懂前后端；
4. OWASP Top10：在 DVWA/sqli-labs/upload-labs 逐个漏洞手工验证；
5. 系统渗透：在 VulnHub 练"打 Web → 拿 shell → 提权 → 拿 flag"的完整链路；
6. 内网基础：在专用内网靶场（域环境）理解横向移动概念与检测；
7. 安全开发：写端口扫描、弱口令、注入检测等脚本；
8. 设备与日志：防火墙/WAF/IDS、日志分析。

## 四、漏洞在靶场的验证思路（教学级，最小 PoC）

> 原则：以"看到漏洞现象、能稳定复现"为度，不读、不改、不删真实数据。

| 漏洞 | 输入点 | 原理性验证 payload（示意） | 成功判据 | 对应防御 |
|------|--------|------------------------------|----------|----------|
| SQL 注入 | 登录/查询参数 | 单引号看报错；`' OR '1'='1`；`1 ORDER BY n--` 判列数 | 永真登录、数据回显、字段错位 | 参数化/预编译、`#{}` |
| XSS | 评论/搜索/昵称 | `<script>alert(1)</script>` | 页面弹窗、脚本被执行 | 输出编码、CSP、HttpOnly |
| 命令注入 | ping/诊断功能 | `8.8.8.8 && id`、`8.8.8.8; whoami` | 返回额外命令结果 | 不拼 shell、参数化、白名单 |
| 文件上传 | 上传点 | 先传 `.txt` 确认，再验证扩展名/解析 | 非法文件被接受/可访问 | 白名单、最后一个点、目录隔离 |
| 路径穿越 | 下载/读取参数 | `../../../../etc/passwd` | 读到上级目录文件 | normalize + 目录边界校验 |
| 越权 | ID/会话参数 | 改 ID/换账号访问他人数据 | 看到不属于自己的数据 | 对象级鉴权（BOLA） |
| 弱口令 | 登录/SSH/服务 | 用靶场内置弱口令字典 | 登录成功 | 锁定、MFA、强口令 |
| SSRF | URL 抓取 | 让靶机请求内网/回环地址 | 探测到内网响应 | 白名单、禁内网 IP |
| CSRF | 敏感操作 | 构造跨站表单（无 Token 时） | 未操作却被执行 | CSRF Token、SameSite |

练习时务必理解：**payload 为什么生效（根因）、代码哪里写错了（污点）、怎么改（防御）**。这三件事会写在报告里，也是面试官最看重的。

## 五、工具的合法用途（授权靶场内）
- **Burp Suite**：浏览器代理抓包、Repeater 重放修改请求、Intruder 理解参数；用于分析自己靶机的请求，不用于绕过他人系统防护。
- **sqlmap**：在授权的靶场验证 SQL 注入与读取数据，理解其判定过程；正式测试遵循授权范围，不拖取无关数据。
- **Nmap**：扫描自己的靶机，学习端口/服务/版本识别；不得扫描未授权主机。
- **中国蚁剑/哥斯拉等**：仅在自己靶机的 Webshell 上连接，用于理解管理端原理，掌握其产生的流量特征以便检测。
- **目录/子域名工具**：只对授权资产或靶场使用。

## 六、攻防对照（本项目的核心价值）
每个攻击动作都在日志里留下痕迹，练习时同步做两件事：
1. 打 Web 时打开靶机 Web 访问日志，看 payload 在日志里长什么样、状态码如何变化；
2. 爆破、上传、命令执行时，看主机认证日志、进程与防火墙外连日志。

这样你练的不只是"打进去"，还能说出"蓝队在日志里看到什么、该怎么配规则、该怎么修"。这正是 SecAgent 多 Agent 研判在做的事：告警 → 多源日志关联 → 攻击链还原 → 处置建议。

## 七、从靶场到报告
每打通一个漏洞，记录：测试位置、请求与 payload、复现步骤、成功截图/证据、风险等级、修复建议。这些构成《渗透测试报告》的最小单元（见《渗透测试报告编写与漏洞复测》）。
