# 越权访问与权限绕过（CWE-639 / CWE-862 / CWE-285）

## 一、原理
越权是指应用没有正确校验"当前登录用户是否有权操作目标数据"，导致用户可以访问或操作他人的数据。越权的本质是只校验了"是否登录"，没有校验"是否是这条数据的主人"。

## 二、两种类型
- **水平越权（IDOR）**：同权限用户访问他人数据。如把 `orderId=1001` 改成 `1002` 就能看到别人订单；会话 ID、用户 ID、文件 ID 由客户端可控。
- **垂直越权（权限提升）**：低权限用户访问高权限功能。如普通用户直接访问管理员接口 `/admin/**`、调用仅管理员可用的接口。

## 三、常见场景
- 直接对象引用（IDOR）：URL/参数中的 `id`、`uid`、`sessionId`、`docId`；
- 接口只在前端隐藏菜单，后端不鉴权；
- 只校验登录态，不校验数据归属；
- 多租户系统未做租户隔离；
- 修改请求方法、加 `X-Forwarded-For`、改请求头绕过鉴权。

## 四、危害
- 泄露他人隐私、订单、聊天、文件；
- 普通用户执行管理操作（增删用户、改配置）；
- 多租户数据串库，造成大规模数据泄露。

## 五、防御
1. **服务端统一鉴权**：所有接口默认拒绝，显式声明需要的权限；不要信任前端隐藏。
2. **对象级权限校验（BOLA）**：每次访问/修改数据，都在服务端比对"当前用户身份 + 该资源归属"，不归属于当前用户即拒绝。
3. **基于角色的访问控制（RBAC）**：在接口层做功能级权限校验，管理员接口独立鉴权。
4. **标识不可猜**：用随机、不连续的 ID/UUID 替代自增 ID（但不能替代权限校验）。
5. **会话与用户绑定**：会话 ID 服务端生成、与用户绑定，设置 TTL，不允许客户端任意指定。
6. **多租户隔离**：所有查询带租户条件，做行级/数据级隔离。

## 六、测试方法
- 水平越权：抓包替换 ID/会话，尝试访问 A 用户的数据；
- 垂直越权：用普通用户 Token 请求管理员接口；
- 未授权访问：不登录直接访问接口，看是否返回数据。

## 七、与项目关联
原始项目的会话 ID 由客户端传入、用 Map 存储且未做归属校验，存在会话枚举/越权风险；改造后增加了接口 Token 鉴权、会话 TTL 与上限，生产环境应进一步做会话与用户绑定及数据归属校验。
