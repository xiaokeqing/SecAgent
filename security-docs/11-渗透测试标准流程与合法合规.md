# 渗透测试标准流程与合法合规

## 一、前提：合法性与授权（红线）
渗透测试是在**书面授权**范围内，对目标系统进行模拟攻击以发现风险的安全服务，与非法入侵的唯一本质区别是**授权**。

- 必须签订授权书/测试合同，明确测试范围（IP、域名、系统）、时间窗口、允许手法、联系人、应急电话。
- 禁止超出范围、禁止在未授权时段进行破坏性操作、禁止数据外泄、禁止影响业务可用性。
- 对数据保密，测试结束交付报告并删除过程数据。
- 相关法律：《网络安全法》《数据安全法》《个人信息保护法》《刑法》第 285/286 条等。无授权测试即可能构成违法犯罪。

## 二、标准流程（PTES）
1. **前期交互**：确认目标、范围、时间、授权、业务与联系人。
2. **信息收集**：
   - 被动收集：域名、备案、子域名、搜索引擎、公开资产、泄露信息（不接触目标）；
   - 主动收集：IP 段、端口、服务指纹、Web 指纹、目录结构（需在授权范围内）。
3. **威胁建模**：分析资产、入口、信任关系，确定攻击面与优先级。
4. **漏洞分析**：结合指纹匹配已知漏洞、配置缺陷、弱口令、Web 漏洞，手工验证。
5. **渗透利用（受控）**：在授权范围内验证漏洞可利用性，**以证明为限，不做破坏**。
6. **后渗透**：评估影响（权限、数据、横向），记录证据，不长期驻留、不植入后门。
7. **报告**：输出漏洞清单、复现过程、风险等级、修复建议，支持复测。

## 三、常用方法论框架
- **OWASP Top 10 / OWASP Testing Guide**：Web 测试清单；
- **PTES**：通用渗透测试执行标准；
- **OSSTMM**：安全测试方法论；
- **MITRE ATT&CK**：攻击行为与战术技术矩阵，用于映射和研判；
- **Cyber Kill Chain**：攻击链阶段分析。

## 四、测试类型
- **黑盒/白盒/灰盒**：按对目标信息掌握程度区分；
- **Web 测试、主机测试、内网测试、移动测试、代码审计**；
- 从视角区分：外部测试、内部测试、红蓝对抗。

## 五、漏洞验证与风险评级
- 用**最小 PoC** 证明可利用，避免读取/破坏真实数据；
- 风险等级结合 CVSS（机密性/完整性/可用性、攻击途径、复杂度、权限要求）与**业务影响**综合评定；
- 典型定级：可未授权 RCE/拖库为严重；越权访问敏感数据为高危；反射型、信息泄露为中低危。

## 六、防御方视角（蓝队/SOC 对应）
- 授权测试的攻击流量会在日志中留下痕迹，可据此检验检测规则；
- 信息收集阶段（扫描、指纹）、利用阶段（payload、异常状态码）、后渗透阶段（异常登录、外连）对应不同监测点。

## 七、与项目关联
SecAgent 的知识库按 OWASP/PTES 组织，多 Agent 研判覆盖 Kill Chain 各阶段，可辅助蓝队理解攻击者的测试思路、识别对应攻击行为，并将漏洞原理与修复建议作为可检索知识，支撑安全服务与渗透报告的漏洞描述、复现与加固建议撰写。
