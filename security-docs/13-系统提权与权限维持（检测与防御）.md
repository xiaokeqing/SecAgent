# 系统提权与权限维持（检测与防御视角）

> 本篇从蓝队/防御视角梳理攻击者提权与持久化的类型、痕迹与排查方法，不提供具体漏洞利用代码。理解攻击面是为了做好检测、加固与应急。

## 一、权限提升（Privilege Escalation）

### 类型
- **垂直提权**：普通用户提权到管理员/root/SYSTEM；
- **水平越权**：访问同权限其他用户数据（见越权专题）。

### 常见提权面（用于加固，不是利用）
- **内核/系统漏洞**：未打补丁（如过期的 OS 补丁），攻击者利用已知提权漏洞。
- **Linux 配置缺陷**：
  - 高权限 SUID/SGID 文件；
  - 以 root 运行的计划任务/服务配置可写；
  - sudo 过度授权（NOPASSWD、可执行危险程序）；
  - 可写脚本、敏感目录权限错误。
- **Windows 配置缺陷**：
  - 服务路径未加引号、服务二进制/注册表权限可写；
  - 计划任务以高权限运行且脚本可写；
  - 高权限令牌、UAC 配置过松；
  - 始终安装组成员、本地管理员组过大。
- **弱口令/凭据泄露**：获得管理员密码、配置文件中的凭据、密码复用。
- **数据库/中间件提权**：以高权限运行的服务、UDF、外部脚本。

### 检测痕迹
- 异常的高权限进程由普通用户会话派生；
- 普通用户执行 whoami/net user/添加账号/访问敏感目录；
- Linux 中 `sudo` 失败/成功、异常 SUID 文件、内核漏洞利用特征（可疑临时文件、崩溃）；
- Windows 事件：4672（特权登录）、4624 类型 9（新凭据）、4720/4732（建账号/加组）、4697（创建服务）、4698（计划任务）；
- 时间线：Webshell/登录后很快出现提权、提权后新建账号或服务。

### 防御
- 及时打补丁、关闭不必要服务、最小化安装；
- 最小权限：服务低权限运行、收敛 sudo 与本地管理员、启用 UAC；
- 定期基线检查：SUID、服务/任务权限、文件权限；
- 凭据管理：禁止明文密码、改默认口令、密钥集中管理；
- 部署 EDR/HIDS 监控特权提升行为。

## 二、权限维持（Persistence）

### 原理
攻击者获得权限后，为了在系统重启、密码更改、首次后门被清除后仍能访问，会建立持久化。

### 常见位置（排查清单）
- **Linux**：
  - 计划任务（`crontab -l`、`/etc/cron.*`）、启动脚本（`/etc/init.d`、`/etc/systemd/system`、`rc.local`）；
  - SSH 公钥（`~/.ssh/authorized_keys`）、后门账号、alias；
  - 替换系统命令、植入恶意模块、开机自启服务。
- **Windows**：
  - 启动目录（`shell:startup`）、注册表 Run/RunOnce、Winlogon；
  - 服务（services.msc）、计划任务（taskschd）；
  - 后门账号（含隐藏/带 `$` 账号）、RDP/WMI 持久化；
  - DLL 劫持、WMI 事件订阅。
- **Web 层**：Webshell、内存马、模板/插件、后门文件。

### 检测
- 启动项、服务、计划任务、注册表的基线对比；
- 异常二进制路径、无签名/未知签名、异常父进程；
- 新增账号、新增 SSH key、定时任务外连；
- Sysmon/EDR 记录服务创建、注册表持久化键、网络回连。

### 清除与防御
- 对照基线逐项删除持久化项、后门账号、公钥；
- 全盘查杀并排查内存马；
- 修复最初入口（漏洞、弱口令）并全量改密；
- 建立白名单与变更监控、基线巡检、备份与镜像留存。

## 三、与应急/研判的关系
提权与权限维持是 Kill Chain 的"权限提升/持久化"阶段。研判时若已确认 Webshell 或 SSH 登录成功，必须进一步检查是否已提权、是否落了持久化、是否横向移动，仅删 Webshell 不排查持久化会导致"清完又来"。对应处置流程见《安全事件分级与处置流程》。
