# 安全事件分级与处置流程

## 一、事件分级（参考 PDR / PDCERF）

| 等级 | 判定 | 典型场景 |
|------|------|----------|
| 严重（P1） | 已失陷、影响核心业务或数据 | RCE/Webshell 成功、勒索、数据泄露、域控失陷 |
| 高危（P2） | 已部分突破或存在明确利用 | 爆破成功、SQL 注入可拖库、未授权访问敏感系统 |
| 中危（P3） | 有攻击行为但未证实成功 | 扫描、爆破失败、单点可疑请求、低危漏洞探测 |
| 低危（P4） | 噪声、未命中的尝试 | 单个 404、常规探测、误报 |

分级要看：是否成功、影响范围、是否可利用、是否涉及核心数据。

## 二、应急响应流程（PDCERF）
1. **准备 Preparation**：预案、工具、联系方式、权限、备份。
2. **发现 Detection**：告警、SIEM、日志、人工上报，确认事件。
3. **抑制 Containment**：止损、隔离主机/IP、断网、封禁、停用账号，防止扩散。
4. **根除 Eradication**：清除后门、Webshell、恶意账号、持久化，修复漏洞。
5. **恢复 Recovery**：从可信备份恢复，验证后上线，加强监控。
6. **跟踪 Follow-up**：复盘、输出报告、更新规则与基线。

## 三、黄金处置原则
- **先止血、再溯源**：明确已扩散的先隔离，但要尽量保留证据。
- **证据保全**：内存、日志、样本、镜像；避免在原始证据上直接操作。
- **时间线优先**：用时间把"入口→利用→落地→持久化→横向→外连"串清楚。
- **根因修复**：只清后门不堵漏洞会复发，必须修复入口并改密。
- **最小影响沟通**：同步业务、领导、客户，按规定上报。

## 四、常见事件处置速查
- **SSH 爆破**：封 IP、失败锁定、禁密码登录、确认是否有成功登录、查后门、改密。
- **Webshell/RCE**：隔离、备份 Web 目录与日志、删马、定位入口漏洞、改密、检测内存马。
- **SQL 注入**：确认是否拖库、临时加 WAF、修代码（参数化）、审计数据库。
- **挖矿**：杀进程、清 cron、阻断矿池、查入口（弱口令/未授权服务）。
- **勒索**：断网、找备份、定家族、保样本、补漏洞，不轻易付赎金。

## 五、研判告警时的判定要点
- 是真阳性还是误报？（多源印证）
- 成功了吗？（登录成功、回显 200、文件落地、外连成功）
- 影响哪些资产和数据？
- 攻击者到了 Kill Chain 的哪一步？
- 先做什么止损、再做什么清除、怎么防复发？

## 六、与项目关联
多 Agent 研判产出的每条告警都应能给出上述结论：等级判定、证据链、攻击链阶段、IOC 与抑制/根除/恢复建议，相当于把 PDCERF 中"发现—研判—抑制建议"环节自动化。
