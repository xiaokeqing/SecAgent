# 数据库与中间件安全加固

> 数据库、Web 中间件、缓存是运维和渗透的高频目标，也是挖矿、勒索、拖库的常见入口。安全运维需掌握其部署与安全配置。

## 一、数据库安全（MySQL/Oracle 等）

### 常见风险
- 弱口令、默认账号（root/sa）、密码复用；
- 管理端口暴露公网（3306/1433/1521）；
- 权限过大（业务账号用 DBA/root、FILE 权限）；
- SQL 注入（应用层，见 SQL 注入专题）；
- 未授权访问、历史漏洞、备份泄露；
- 数据库勒索、数据被导出。

### 加固
1. 最小权限：业务库账号只授权所需库/表，不用 root 连接业务；
2. 强口令、禁止默认账号、删除测试库；
3. 监听绑定内网、防火墙白名单、不暴露公网；
4. 禁用或限制危险功能（如 MySQL `FILE`、`INTO OUTFILE`、xp_cmdshell）；
5. 定期备份、离线保存、验证恢复；
6. 打补丁、升级版本、关闭不必要组件；
7. 开启审计日志、慢查询/登录日志、异常导出监控；
8. 传输加密（TLS）、敏感字段加密存储；
9. 数据库与应用之间网络隔离。

## 二、Redis 安全（未授权是高发入侵点）

### 风险
- 默认无密码、绑定 0.0.0.0，导致未授权访问；
- 攻击者可写 SSH 公钥、写计划任务、写 Webshell、主从复制加载模块 RCE；
- 是挖矿木马、Webshell 的常见入口。

### 加固
1. 设置强密码（`requirepass`），高版本启用 ACL；
2. 仅绑定内网/本地（`bind 127.0.0.1`），不暴露公网；
3. 用低权限用户运行 Redis，禁止以 root 运行；
4. 禁用/重命名危险命令（`CONFIG`、`FLUSHALL`、`SLAVEOF`、`MODULE` 等）；
5. 关闭或限制持久化目录权限，开启保护模式；
6. 网络隔离 + 防火墙 + 认证；
7. 升级到稳定版本，修复已知漏洞。

## 三、Web 中间件（Tomcat/Nginx/Apache）

### Tomcat
- 风险：manager 弱口令（可部署 war 拿 Webshell）、AJP Ghostcat（CVE-2020-1938）、默认应用、目录列举；
- 加固：删除 manager/docs/examples 或强口令+IP 限制、禁用 AJP 或加 secret、最小权限运行、升级、关闭目录列表、错误页不泄露版本。

### Nginx
- 风险：错误配置、路径穿越、解析问题、未授权访问、反向代理把内网服务暴露；
- 加固：最小化模块、关闭 autoindex、合理配置 alias/location、限制请求体、TLS、安全响应头、访问日志、不把管理面经代理暴露。

### Apache/IIS
- 关闭目录列举、最小化模块、打补丁、最小权限、日志审计。

### 通用
- 改默认端口/控制台口令（仅辅助）；
- 管理后台不暴露公网、加 VPN/IP 白名单；
- 中间件版本纳入 CVE 监控（SCA）；
- 后端组件（Spring/Shiro/Struts/Fastjson/Log4j）及时升级。

## 四、常见服务安全
- **SSH**：密钥登录、禁 root、限源（见系统加固）；
- **FTP**：明文传输，改 SFTP/FTPS，隔离目录、强口令；
- **邮件/共享**：最小权限、防匿名访问；
- **容器/编排**：Docker API 不暴露、不挂 docker.sock、镜像最小化、非 root 运行、K8s RBAC 与 Secret 管理；
- **消息队列/ES/Mongo**：默认无认证、暴露公网是常见入口，需加认证、绑内网。

## 五、排查与研判
- 异常外联、高 CPU（挖矿）、数据库大量导出、Web 目录出现后门文件、配置被改（写计划任务/公钥）；
- 中间件/数据库日志中的异常登录、成功登录 IP、命令执行（如 Redis 的 CONFIG 操作）；
- 处置：断网、恢复密码、关闭未授权、清除持久化、修复入口、从备份恢复。

## 六、与岗位/项目关联
- 安全运维岗要求会部署配置 MySQL、Web 服务器并做安全加固；
- 安全服务交付中，Redis 未授权、Tomcat 弱口令、Web 组件 RCE 是扫描和报告的高频项；
- SecAgent 的多 Agent 研判里"挖矿/Webshell/外连"场景，常见根因正是上述数据库与中间件配置缺陷，可在知识库中关联检索加固建议。
