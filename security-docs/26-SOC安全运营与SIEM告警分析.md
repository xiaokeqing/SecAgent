# SOC 安全运营与 SIEM 告警分析

> 安全运营服务工程师负责 7×24 监控、告警研判、处置与复盘。SecAgent 的多 Agent 安全研判，本质上是对 SOC 一线分析流程的自动化辅助。

## 一、SOC 是什么
SOC（Security Operations Center，安全运营中心）是集中进行安全监控、检测、分析、响应的团队与平台体系。常见组成：
- 人员：一/二/三线分析师（L1 值守研判、L2 深度分析、L3 应急/专家）；
- 平台：SIEM、SOC、EDR、NDR、WAF、IDS、堡垒机、日志平台、威胁情报、SOAR；
- 流程：监控、告警、研判、处置、复盘、优化。

## 二、SIEM 与日志
- **SIEM（安全信息与事件管理）**：集中采集、解析、关联各类日志和告警，做规则匹配、关联分析、检索与可视化。
- 常见数据来源：防火墙、WAF、IDS/IPS、VPN、EDR、服务器/主机、数据库、AD 域控、Web/中间件、应用、认证系统、云平台。
- 核心能力：日志归一化、关联规则、UEBA、威胁情报匹配、告警工单、大屏。
- 数据管道概念：采集（Agent/Syslog/API）→ 解析（字段化）→ 存储 → 检测规则 → 告警 → 处置。

## 三、SOAR（自动化编排与响应）
- 通过剧本（Playbook）把"某告警 → 自动查询情报/资产/日志 → 自动隔离/封禁/通知"等动作串起来；
- 常见动作：封禁 IP、隔离主机、禁用账号、查威胁情报、建工单；
- 与 SecAgent 的关系：多 Agent + Tool Calling 是"智能研判"的形态，可作为 SOAR 中自动汇聚证据、给出研判结论的一环，但**高危处置动作（隔离、删除）仍需人工确认**。

## 四、一条告警的研判流程（L1 一线）
1. **看告警**：名称、类型、严重等级、命中规则、时间、源/目的资产、五元组。
2. **看资产**：被攻击的是什么系统、重要性、暴露面。
3. **查上下文**：
   - 同一源 IP 还做了什么（扫描、爆破、其他攻击）；
   - 该主机前后日志（认证、Web、主机、外连）；
   - 时间线对齐。
4. **查情报**：源 IP/域名/哈希是否命中威胁情报（C2、矿池、扫描器）。
5. **判断成功与否**：是否 200/回显、是否登录成功、是否落地文件、是否外连。
6. **定性定级**：真阳性/误报、严重程度、是否需要升级。
7. **处置**：封堵、隔离、止损、通知、建工单。
8. **闭环**：记录研判结论与处置，复盘优化规则。

## 五、真阳性 vs 误报
- 误报常见原因：规则过宽、测试流量、内部安全扫描、爬虫、正常业务匹配了特征；
- 判定要点：多源印证、是否有成功迹象、情报是否命中、资产是否真实暴露；
- 目标是降低误报、提升信噪比（持续调优规则、白名单、资产信息）。

## 六、MTTR 与运营指标
- MTTD（平均检测时间）、MTTR（平均响应/恢复时间）；
- 告警量、有效告警率、误报率、关闭时长、规则覆盖率；
- 值班 SLA、升级机制、漏报复盘。

## 七、威胁狩猎（Threat Hunting）
在没有明确告警时，基于假设与 ATT&CK 主动搜寻潜伏威胁，例如：
- 异常的内网横向、罕见进程、异常 PowerShell、计划任务外连；
- 用日志查询构建狩猎场景，形成新的检测规则。

## 八、安全运营常用结论产物
- 告警研判记录、安全事件报告、日报/周报、处置工单、规则优化清单、IOC 封禁清单。

## 九、与项目的对应关系（重点）
SecAgent 把上述 L1 流程做了产品化映射：
- **Planner（规划）**：分析安全告警，规划要查哪些证据（对应研判流程第 1～4 步）；
- **Executor（执行）**：通过工具调用查询安全告警、主机/Web/防火墙日志、知识库，完成多源关联与证据印证（对应查上下文与情报）；
- **Supervisor（监督）**：汇总输出《安全事件研判报告》，给出攻击链、IOC、等级与处置建议（对应定性定级与处置）；
- 预置的 SSH 爆破、SQL 注入、Webshell、目录扫描场景，是 SOC 高频真实告警。

面试可讲：自己做的是"用 RAG + 多 Agent 辅助安全运营一线研判"，解决告警多、需要跨系统查日志、研判耗时的问题，并强调自动化结论必须人工复核、高危处置需授权。
