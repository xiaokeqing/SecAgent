# 路径穿越（Path Traversal，CWE-22）原理与防御

## 一、漏洞描述

当程序把用户可控的文件名/路径直接拼接到目标目录，却没有校验最终路径是否仍然位于该目录之内时，攻击者可以通过 `../` 等方式跳出目录，实现任意文件读写。

- CWE 编号：CWE-22（对路径名限制不当，导致目录受限路径逃逸）
- OWASP 归类：A01 失效的访问控制 / A05 安全配置错误
- 典型攻击：上传文件写成 `../../etc/passwd`、下载接口读取任意文件、`..\\..\\windows\\win.ini`（Windows）

## 二、本系统中的原始问题（已修复）

原始文件上传接口关键代码：

```java
String originalFilename = file.getOriginalFilename();
Path filePath = uploadDir.resolve(originalFilename).normalize();
Files.copy(file.getInputStream(), filePath);
```

问题在于：
1. 完全信任客户端传来的原始文件名；
2. 虽然调用了 `normalize()`，但只做了规范化，没有判断规范化后的路径是否仍在上传目录内。

攻击者构造文件名 `..\..\..\..\Windows\Temp\evil.jsp` 或 `../../tmp/x.txt`，文件会被写到上传目录之外。

## 三、复现要点（仅在本地授权环境验证）

- 正常上传：`curl -F "file=@test.txt" http://localhost:9900/api/upload`
- 攻击载荷：文件名中带 `../` 或 `..\`、绝对路径、Windows 盘符 `C:\`、空字节 `%00`、解析漏洞 `x.asp;.jpg`。
- 旧版本会把文件落到上传目录外；修复后应返回 400「非法文件名」。

## 四、防御方案（本系统已实现）

1. **不要直接使用原始文件名落盘**：对文件名做白名单净化，只允许中英文、数字、点、下划线、连字符、空格、括号；拒绝 `..`、`/`、`\`、`:`、空字节。
2. **提取最后一段**：即使客户端伪造路径，也只取最后一个路径分隔符后的文件名。
3. **扩展名单独校验**：取最后一个点之后的扩展名，白名单比较（如仅 txt、md）。
4. **规范化后再做目录归属校验（关键且不可省略）**：
   ```java
   Path base = uploadDir.toAbsolutePath().normalize();
   Path target = base.resolve(safeName).normalize();
   if (!target.startsWith(base)) {
       throw new InvalidFileNameException("非法的文件路径：已拒绝目录穿越");
   }
   ```
5. **规避系统保留名**：Windows 下拒绝 NUL、CON、AUX、PRN、COM1-9、LPT1-9。
6. **上传目录最小权限**：上传目录放在 Web 根目录之外，禁止执行权限，不允许脚本文件（.jsp/.php/.asp/.sh）。

## 五、易踩的坑

- 只做 `normalize()` 而不做 `startsWith(base)` 校验，等于没防。
- 用黑名单替换 `../` 不可靠，可被 `....//`、编码、大小写、双写绕过。
- 只在前端校验可被直接请求 API 绕过，必须在服务端校验。
- 扩展名取「第一个点」或用 `contains` 判断会被 `x.php.jpg` 等多扩展名绕过，应取最后一个点。

## 六、检测特征

- 日志/请求中出现 `../`、`..\\`、`%2e%2e`、`%252e`、绝对路径、盘符、`%00`。
- 上传目录之外出现文件；Web 目录出现异常脚本文件。
